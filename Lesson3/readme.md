### Почему я и не только я считаю IIS тривиальным методом ?

Дело в том что это старый и очень низкоуровневый метод.

1. Вам придется натсраивать виртуальную машину вручную. А это по факту не маленькая задача так как вам надо настроить следующее:

- Firewall
- IIS settings
- App environment settings
- SSL
- sFTP (опционально)

Дело в том что secure FTP можно и не настроить, но есть беда с интеграцией обновлений (Привет Эльнуру). Каждый раз при обновлении приложения вы будете делать dotnet publish и перетаскивать папку на сервер вручную. ВРУЧНУЮ !!!
Если настроить FTP в важей папке проекта на сервере, то хотя бы можно автоматизировать этот процесс.

# Deploy с помощью Docker

Этот способ тоже подразумевает использование Azure Web App Service вместе с Azure Container Registry.

Такой расклад очень хорошо для широкомастшабных проектов. Вы уже достаточно взрослые чтобы понять разницу между разработкой в ширь и в глубь. В ширь это использование разных технологий в вашем проекте. В глубь это глубокое использование одного.

Давайте разбирать в каком случае благоприятно использовать вариант с Docker ? Ответ: всегда.

Тема с гитхаб конечно классная, но Docker не отстает а даже превосходит его. Например, если у вас в приложении есть отедельные:

- AuthApiService
- WorkerApiService
- React App
- Ms Sql
- Redis cache

В первом случае вам пришлось бы загружать отднльно почти все ресурсы не считая базы данных. При чем базу данных пришлось бы тоже загрузить отдельно, если оба `api` должны были бы связываться с ним.

В случае с Docker вы все собираете в один `image`.
