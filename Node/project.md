# **Проектная работа: Разработка двух API на NestJS (AuthAPI + ShopAPI)**

## **Описание проекта**

В рамках этой проектной работы студенты должны создать два API с использованием **NestJS**:

- **AuthAPI** – сервис аутентификации и авторизации пользователей.
- **ShopAPI** – API интернет-магазина, в котором пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы.

Оба API должны быть связаны между собой. AuthAPI отвечает за регистрацию и авторизацию пользователей, а ShopAPI должен проверять, авторизован ли пользователь перед выполнением определённых действий (например, перед оформлением заказа).

---

## **Технологии и требования**

- **NestJS** – основной фреймворк.
- **TypeScript** – язык программирования.
- **Passport.js** – для аутентификации (JWT).
- **DTO и валидация данных** – использование `class-validator` и `class-transformer`.
- **CORS** – настройка разрешений на доступ к API.
- **Swagger** – документация API с использованием `@nestjs/swagger`.
- **PostgreSQL или MongoDB** – база данных для хранения пользователей и товаров.
- **Docker** _(по желанию)_ – контейнеризация приложения.

---

## **Функциональные требования**

### **1. AuthAPI (Сервис аутентификации)**

#### **Маршруты**

- `POST /auth/register` – регистрация пользователя.
- `POST /auth/login` – вход в систему, возвращает JWT-токен.
- `GET /auth/profile` – получение профиля пользователя (защищённый маршрут).
- `POST /auth/logout` _(по желанию)_ – выход из системы (удаление токена, если используется сессионная аутентификация).

#### **Функциональность**

- Регистрация пользователей с валидацией данных (email, пароль, имя).
- Аутентификация с использованием JWT.
- Хранение паролей в **bcrypt** (хеширование).
- Защита маршрутов с использованием `AuthGuard`.
- Разграничение ролей (например, **user** и **admin**).

---

### **2. ShopAPI (Магазин товаров)**

#### **Маршруты**

- `GET /products` – получение списка товаров.
- `GET /products/:id` – получение информации о товаре.
- `POST /products` – добавление товара (**только для администратора**).
- `PUT /products/:id` – обновление товара (**только для администратора**).
- `DELETE /products/:id` – удаление товара (**только для администратора**).
- `POST /cart` – добавление товара в корзину.
- `GET /cart` – просмотр корзины пользователя.
- `POST /orders` – оформление заказа (**только для авторизованных пользователей**).

#### **Функциональность**

- Защита маршрутов с JWT (пользователь должен быть авторизован, чтобы добавить товар в корзину или оформить заказ).
- Разграничение прав (обычный пользователь vs. администратор).
- Хранение данных в **PostgreSQL/MongoDB**.
- Использование DTO для валидации данных.
